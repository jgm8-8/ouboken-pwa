# Ouboken PWA 1.0.1

既存のPython / Windows EXE版とは独立した、iPhone用の静的Webアプリです。このフォルダだけを公開してください。親フォルダの `data`、`img`、EXE、応募者情報、APIキーは公開物に含めません。

## 使えること

- 写真を複数追加し、端末内のOCRでコード候補を読む。確認後、券別の自由記述を編集し、複数券のZIPをまとめて出力。
- 応募者情報・共通回答・券別回答・出力時の内容・手動の応募済み記録を端末内へ自動保存。
- ZIP内の `コピー一覧.txt` は改行区切り。先頭ゼロを保持、空欄と選択式回答は省略。`次の位置.txt` は `1`。既存のショートカット方式を使えます。
- 応募券一覧の削除ボタン、または個別画面の「この応募券を削除」から、不要な券を削除。確認後、その券の写真・回答・履歴も削除します。
- トップの「バックアップを作成」「バックアップから復元」で、写真・応募者情報・回答・履歴をまとめて保存・復元。パスワードは不要。
- 一覧の「選択」から複数券のステータスをまとめて変更。応募済みは利用者の手動記録です。
- 一覧は小さなサムネイルを表示し、画面外の画像は必要になるまで読み込みません。既存の写真も対応します。
- バックアップのファイル名と復元画面に作成日時・応募券の枚数を表示。未確認の途中入力も保存できます。
- 設定の「全データを削除」で、この端末の写真・応募者情報・回答・履歴をまとめて削除。確認画面から先にバックアップを作成できます。キャッシュやダウンロード済みファイルは別管理です。
- 初回の読み込みが済めばアプリとOCRはオフラインで利用可能。応募先を開くときはネット接続が必要。

応募の送信・自動入力・応募サイトの操作は行いません。文章整形は本人のAPIキーを使い、ブラウザからOpenAIへ直接接続します。元のPython版の文章生成設定は変更していません。

## iPhoneで使う

1. HTTPSの公開URLをSafariで開き、設定の「オフライン準備済み」を確認。
2. Safariの共有 →「ホーム画面に追加」。ホーム画面から起動したアプリで写真を追加。
3. コード確認 → コードごとの自由記述 → ZIPにまとめる。

Safariのタブとホーム画面のアプリで保存領域が分かれる場合があるため、最初にホーム画面へ追加してから使ってください。既に入力した場合はバックアップを保存し、ホーム画面側で復元します。

通常の保存先はこの端末・この公開URLのIndexedDBです。PC版のDPAPI暗号化とは異なり、ブラウザ内の台帳自体はアプリ独自の暗号化をしていません。`.ouboken` バックアップもパスワードなし・暗号化なしです。写真・住所をサーバーへ送信しません。文章整形を押した場合のみ、選んだ自由記述をOpenAIへ直接送信します。アプリ配信へのアクセス記録はホスティング側に残り得ます。

更新時は現行版と最新の待機版だけを保持し、更新を適用した後に古いキャッシュを整理します。

サイトの閲覧データ削除、端末交換、公開URL変更などで台帳を失うことがあるため、バックアップをファイルへ保存してください。作成→「ファイルに保存」で端末のファイルへ保存し、復元ではファイルを選んで内容の置き換えを確認します。旧形式のパスワード付きバックアップは、更新前の版で復元して新形式を作成してください。PC版の台帳を自動移行する機能はありません。

OCRはPP-OCRv4の文字認識モデルを同梱。応募券の左右のコード枠を検出し、コード①の傾きを補正してから読みます。Oと0、QとGなどの誤認識は券面で修正してください。読めなかった写真も保存され、手入力できます。更新後の取り込み済み写真は、ホームの「その他の操作」→「未確認の写真を再読取」で読み直せます。確認済みのコード・回答・出力履歴は変更しません。JPEG・PNG・WebP対応。HEICはJPEGへ変換して選び直してください。一度に最大150枚、各25MB以内。大きい写真は最大辺2000pxに縮小し、1枚ずつ処理します。読み取り中はアプリを前面に置くと安定します。

### ビルド済みファイルを公開する場合

1. GitHubに空のPublicリポジトリ `ouboken-pwa` を作成。
2. `release/ouboken-pwa-pages.zip` を展開し、中身をリポジトリのルートへアップロード。`index.html` がルートに来るようにします。隠しファイル `.nojekyll` も含めます。
3. Settings → Pages → Sourceを「Deploy from a branch」、Branchを `main` / `(root)` にして保存。
4. デプロイ成功後、上記URLをiPhoneで開きます。

### ソースから公開・更新する場合

`release/ouboken-pwa-source.zip` を展開した中身を空のリポジトリのルートに配置。Settings → Pages → Sourceを「GitHub Actions」に変更。`main` へpushするとテスト・ビルド・公開を実行します。ZIPをそのまま1ファイルとしてアップロードしてもサイトにはなりません。

この公開物に利用者の台帳は含まれません。アプリのURLは友人限定ではなく、アクセスできる人なら使えます。それぞれの端末で保存領域が独立します。

## 開発・検証

Node.js 24 / pnpm 11.25.0。独立したこのフォルダで実行します。

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm preview
pnpm package
```

プレビュー：`http://127.0.0.1:8773/`。既存版の8765とは別です。HTTPのLANアドレスではiPhoneのPWAに必要な機能を確認できません。HTTPSのPages公開URLで確認します。

`dist/` は全OCRモデルを含む静的ファイルです。写真読み取り・保存・ZIP出力にPython・常駐PC・APIサーバーは不要です。文章整形も本人のAPIキーで直接接続するため中継サーバーは不要です。依存ライセンスは `dist/THIRD_PARTY_NOTICES.txt`。CSPの通信先は同じサイトとapi.openai.comに制限しています。OpenAIのAPIキーはこの端末のlocalStorageに保存し、再起動後も保持します。台帳・バックアップ・公開ソースには含めません。

## 保存容量・欠損・重複・状態変更

設定の「端末の保存容量」で、このアプリのCache Storageと写真・回答・履歴の本体容量を表示。ブラウザ管理領域を含まない概算です。「キャッシュを削除」はアプリ・OCRのファイルだけを削除し、台帳や写真を消しません。「キャッシュを再準備」でオンラインから再取得できます。他のサイト・同一ドメイン内の別アプリのキャッシュは削除しません。

起動時、画面へ戻った際、保存・キャッシュ操作後に、台帳が参照する画像とオフライン用ファイルを照合し、不足をトップに赤字表示します。IndexedDB消失や保存券の減少は別のlocalStorageチェックポイントが残っている場合に検知します。すべての領域が同時に消去された場合は初回利用と区別できません。通知は消えた内容の復元を保証せず、バックアップが必要です。

個別画面のステータス選択で「確認済み」に戻すと、記録時の回答を引き継いで編集できます。「要確認」は照合を解除します。以前の出力と変更前の内容は操作履歴に保持。編集後は再出力してから手動の応募済み記録を付けます。

写真追加時に同一ファイルと同一コードの重複を通知。重複写真は追加を省略し、別写真の重複コードはコード欄を空にして候補と注意を残します。読み取り誤りがあり得るため、人が照合します。

## 文章整形

設定の「OpenAI APIキー」に、使う本人のキーを入力します。モデルはGPT5-nano（API名 `gpt-5-nano`）。API利用料はそのキーの所有者にかかります。中継サーバーもCloudflareアカウントも不要です。

キーはこの端末のlocalStorageに保存し、設定画面には値を表示せず設定済みの表示を出します。再読み込み・再起動後も使用できます。「保存したキーを削除」または「全データを削除」で消せます。バックアップ・台帳・ZIP・公開ソースには含めず、別端末への復元後はその端末で入力してください。キーの保存は暗号化していないため、端末を他の人へ渡す際は削除してください。キーをチャットや公開ソースに貼らず、各自の設定画面で入力してください。

共通アンケート・コードごとの自由記述・個別画面のQ8／Q9／感想で「文章を整える」を押すと、その項目のみをOpenAI Responses APIへ送信。住所・コード・写真・選択式回答は添付しません。文章自体に個人情報を含めないでください。入力にない経験・評価・作品などを追加しない指示で整え、採用を押すまで回答を置き換えません。構造化出力・store=false・reasoning effort=minimalを指定し、不正な結果・拒否・未完了・認証エラー・利用上限を処理します。

文章整形はオンライン専用。オフラインでも直接編集とZIP出力は使えます。実際のAPIキーでの通信・出力品質は利用者の実機確認が必要です。`llm-worker/` は別途キーをサーバー保管する方式に戻す場合の参考実装として残しており、現在のPWAからは呼びません。
